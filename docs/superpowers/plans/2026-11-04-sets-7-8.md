# Sets 7 & 8 (Aurora Fjord, Bioluminescent Bay) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Sets 7 and 8, each with one of everything: a world, a visual, an original instrument, a new sky feature, a new weather and new ambience sounds. The new sky and weather reach every world with a sky.

**Spec:** `docs/superpowers/specs/2026-11-04-sets-7-8-design.md` (read it alongside this plan; section numbers below refer to it).

**Architecture:** as the spec's §3. Adds to what Sets 1–6 and builds 230–249 built; the Audio Unit, panel, picker, mapping and sets plumbing are generic.

**Tech stack:** Swift 5.10 tools (Swift 6.1 compiler, Swift 5 mode), SwiftPM, C++17 (`InStrumDSP`), AVFoundation / AudioToolbox, Metal (runtime-compiled MSL, `RenderStack`), SwiftUI, XCTest, GitHub Actions macos-15.

## Global constraints

- macOS 13.0 deployment; the release binary is x86_64; CI tests run on arm64. Code builds for both. Swift's `Float16` is unavailable on Intel: never use it.
- No third-party dependencies. No recordings or samples of any song. No protected library is touched.
- **Sound Core rules:** no allocation, locks or logging on the audio thread; denormals flushed; sample-accurate MIDI; every dial smoothed (`Smoothed`, 20 ms); voices stolen quietest-first with a 20 ms fade; output through `SpaceReverb`, `PeakLimiter` and `softLimit`; tuning within 2 cents; fine tune ±50 cents and transpose ±12 exact within 1 cent.
- **Ambience:** new sources at the END of `ISDAmbienceSource`; ducking and glides as before; panic never silences ambience.
- **Visuals (Smooth rules):** ≤ 1 MP, no per-pixel ray marching, noise ≤ 3 octaves (2 on Smooth where the spec says), no buffers made per frame, flares/glints/swells through `FlashLimiter`, no `pow` of a possibly negative base in any shader (`testShadersSquareWithoutPow` scans new shader sources).
- **Credits:** text and a Spotify link only. Card art original.
- **CI time:** the test job has an 8-minute budget (the suite runs ~2.5 min now). New render tests use the 640 × 360 harness and a few seconds of stepping at most; no test runs a minute of simulated time at 60 fps unless it is a hang check that completes in < 5 s.
- **Names:** sets `aurora-fjord` / **Aurora Fjord** / mood *Awe-struck, cold, electric* (`Mood.electricAwe`); `bioluminescent-bay` / **Bioluminescent Bay** / mood *Magical, secret* (`Mood.secretGlow`). Instruments **Polar Choir** (`polarChoir`, `isPC`, `ISD_ENGINE_POLAR_CHOIR = 6`) and **Plankton Keys** (`planktonKeys`, `isPK`, `ISD_ENGINE_PLANKTON_KEYS = 7`). Visuals **Curtain Lights** and **Glow Wake**. Credits `wings` and `happiness-is-a-butterfly`. Weathers `.humid` ("Humid night") and `.diamondDust` ("Diamond dust"). Hold `.deepNight` ("Deep night", −30°). `AuroraMode` `.follow/.always/.never`.

## Review focus

1. **Leaving a world with Aurora "Always"**: the beach after the fjord must not keep an aurora (the mode is a world parameter passed per step; `SceneDirector.switchTheme` resets nothing in the sky but the next step passes `.follow`). Pinned in Task 4 (`testAuroraModeIsPerStep`).
2. **Panic and instrument switches during a swell or a spark burst**: all-notes-off and all-sound-off stop Polar Choir's voices and Plankton Keys' sparks within 50 ms; nothing sounds by itself. Pinned in Tasks 2 and 3.
3. **Hours-long sessions**: ripple and patch ids wrap; lists capped; the aurora machine's Kp stays in 0…9 over 48 simulated hours; the star texture is built once. Pinned in Tasks 4, 7, 8.
4. **The star texture arriving late** (background build): every world renders before it arrives (procedural fallback) and after; no frame blocks. Pinned in Task 5 (`testSkyRendersBeforeAndAfterTheStarTexture`).
5. **Unusual window shapes** (2.4:1 and 1:1): both worlds keep their keys, jetty/sand and lights inside the view. Pinned in Tasks 7 and 8.

## Rulings recorded while planning

- **RED by construction**: an engine's or a world's tests reference symbols that do not exist yet, so the test target cannot build before the implementation; tests and implementation are pushed together, as in the Sets 5 & 6 run, to save a CI queue. Cost if wrong: none for the code; the tests still have to pass on CI.
- **DSP tuning happens on the local g++ mirror** (`$SP/pad/build.sh`), which compiles `Sources/InStrumDSP/*.cpp` with a small harness; CI runs the Swift tests. Cost if wrong: an x86/arm64 difference shows as a RED and is retuned from CI's printed values.
- **The star catalogue is generated data** (a Python script in the scratchpad reads HYG v4.1 and writes `StarCatalogue.swift`); it is committed as a Swift literal, with the attribution in the header, so the app has no data file to load. Cost if wrong: a 925-row literal (about 60 KB).
- **The star texture lives in Core** as a CPU-built RGBA8 byte array (`StarTexture.build()`), uploaded by the App's `SkyLayer`. Cost if wrong: none.
- **Fireflies and crystals ride the weather layer's ring buffer** as instance kinds 4 and 5. Cost if wrong: none.
- **The cold-sky rule moves to Core** (`WorldWeather.cold(_:)`, from `SnowboundCabinModel.coldSky`), shared by the cabin and the fjord; the cabin's tests keep passing. Cost if wrong: none.
- **Order:** instruments first (preview builds reach Michael early), then the sky and ambience, then the worlds; each card lands with its instrument's app task.
- **Usage:** the planner and integrator run on Fable; implementation subagents and the two final reviewers run on Opus at high effort.
